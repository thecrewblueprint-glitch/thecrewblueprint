# MDQ-001 — Site-Wide Source / Citation / Content Matrix Schema

**Prepared:** 2026-08-31  
**Status:** Complete schema baseline  
**Depends on:** MDQ-000 canonical domain IDs  
**Purpose:** Define a durable claim-level evidence model before the next research and course-build wave.

## Design decision

The matrix will be **logically normalized** rather than one giant manually maintained spreadsheet row. Five linked record types preserve traceability without repeating source metadata thousands of times:

1. **CONTENT** — a route, course, module, lesson, block, claim, question, answer rationale, visual, or boundary statement.
2. **SOURCE** — an external or internal evidence object with owner/version/applicability metadata.
3. **SUPPORT_EDGE** — the exact relationship between one content item and one source.
4. **MEDIA** — rights, model, reviewer, alt text/transcript, and claim relationships for visual/audio/video assets.
5. **REVIEW** — owner/practitioner/legal/learner/a11y/source-freshness dispositions.

A flattened CSV or Sheet can be generated by joining these records. The canonical meaning lives in the fields below.

## Stable ID grammar

IDs must survive wording edits and should not be derived from a sentence hash.

| Object | ID form | Example |
|---|---|---|
| Domain | `D-<3–5 chars>` | `D-LTG` |
| Course/resource | `C-<DOMAIN>-<SLUG>` | `C-LTG-PRODUCTION-FLOW` |
| Module | `M-<course>-NN` | `M-LTG-PRODUCTION-FLOW-01` |
| Lesson | `L-<course>-NNN` | `L-LTG-PRODUCTION-FLOW-001` |
| Block | `B-<course>-NNNN` | `B-LTG-PRODUCTION-FLOW-0001` |
| Claim | `CL-<course>-NNNN` | `CL-LTG-PRODUCTION-FLOW-0001` |
| Question | `Q-<course>-NNN` | `Q-LTG-PRODUCTION-FLOW-001` |
| Answer rationale | `QR-<question>` | `QR-Q-LTG-PRODUCTION-FLOW-001` |
| Visual/media | `V-<course>-NNN` | `V-FLD-ROAD-CASE-001` |
| Source | `S-<OWNER>-<SHORT>-<YYYY/VERSION>` | `S-OSHA-1910-37-CURRENT` |

| Review | `R-<content>-NN` | `R-CL-FLD-ROAD-CASE-0001-01` |

Existing module/lesson identifiers are preserved where they already exist; matrix IDs wrap rather than replace them.

## Content classification enum

Every factual or instructional claim uses exactly one primary classification:

- `external_fact` — external evidence directly establishes the fact.
- `source_backed_instruction` — Crew Blueprint paraphrases evidence into bounded learner instruction.
- `cross_source_pattern` — several sources support a shared operating idea but not one universal rule.
- `practitioner_convention` — field convention supported primarily by identified practitioner/employer/local evidence.
- `manufacturer_or_model_procedure` — applies only to named equipment/version/family.
- `employer_or_venue_procedure` — applies only in the named operational context.
- `crew_blueprint_framework` — instructional sequencing/model created by Crew Blueprint; evidence may motivate it but does not establish it as industry law.
- `safety_boundary` — tells the learner what not to do, when to stop, or who retains authority.
- `assessment_prompt` — question/scenario; source lineage is carried through its rationale.
- `visual_depiction` — image/diagram/video represents a sourced fact, sequence, or framework.
- `navigation_or_ui` — no factual support required unless copy itself makes a claim.

| `verified_at` | date/null | Review date |

### Support-strength rule

A source appearing in a course bibliography does **not** automatically create `direct` support. Each claim needs an edge stating what the source supports.

# 6. Required matrix views

The normalized records must be exportable into these audit views:

1. **Route → claim → source view** — every learner-facing factual/instructional claim on a route.
2. **Source → all content view** — every course/resource using a source; necessary when a source changes.
3. **Safety-critical view** — high/life-safety claims, authority owner, practitioner review, freshness.
4. **Unsupported view** — no verified direct/partial/corroborating support and not explicitly `crew_blueprint_framework`.
5. **Qualification view** — claims that become misleading if their jurisdiction/model/employer qualifier disappears.
6. **Question rationale view** — every assessment answer linked to supporting course claims and sources.
7. **Visual evidence view** — each safety-critical visual linked to source, rights, model/procedure, reviewer and fallback.
8. **Supersession view** — old routes/claims/sources and their current replacements.
9. **Domain completeness view** — MDQ-000 domain state, current routes, research packets, open gaps and review gates.

# 7. Claim granularity rules

Create a separate `CL-*` when any of the following changes:

- the factual proposition;
- the responsible authority;
- the applicable equipment/model;
- the jurisdiction or sector;
- safety consequences;
- the source set necessary to support it.

Do **not** split purely rhetorical sentences that make the same proposition. A paragraph may map to one claim family when all sentences share the same evidence and applicability.

For procedure sequences, each safety-critical or authority-changing step receives its own claim; low-risk explanatory steps may be grouped when source/applicability are identical.

# 8. Assessment mapping rule

Every question must link to:

`Q-*` → `QR-*` → one or more `CL-*` → one or more `SUPPORT_EDGE` → `SOURCE`.

A correct answer cannot be justified only by “the course says so.” If the question tests Crew Blueprint framing, the rationale is labeled `crew_blueprint_framework` and must not be presented as external law or universal practice.

# 9. Publication gate produced by the matrix

A route may be a review draft before full matrix completion. Final publication review requires:

- all high/life-safety claims classified and sourced or explicitly bounded as framework;
- no unresolved `contradicts` edge;
- all model/jurisdiction qualifiers preserved;
- every answer rationale traceable;
- every safety-critical visual has rights + reviewer + fallback;
- superseded sources/claims are not silently active;
- current owner disposition recorded.

This matrix does **not** create certification, qualification, employer authorization, or legal authority.

# 10. Implementation recommendation

Keep the first canonical matrix in repository-readable data rather than a single hand-edited HTML page. Preferred later implementation:

- `research/matrix/content.csv` or JSONL
- `research/matrix/sources.csv` or JSONL
- `research/matrix/support_edges.csv` or JSONL
- `research/matrix/media.csv` or JSONL
- `research/matrix/reviews.csv` or JSONL

Generate human-readable Markdown/HTML audit views from those records. Do not make the generated view the source of truth.
